# source-context

Raw inputs and provenance for this project. The source material the
deliverables are derived from, kept separate from the deliverables
themselves.

What lands here:
- Research notes, papers, datasheets, reference docs the work is built on
- Founding transcripts, project plans, scope docs
- Raw data, field captures, measurements, exports before processing
- Supporting tooling/scripts that generate or sync project artifacts
- Reviews and source reports that inform but aren't the final output

What does NOT land here:
- Shipped deliverables (those live at the project root or in their own dirs)
- Anything tracked elsewhere by convention (BUILD_LOG.md, TODO.md, git history)

Rule of thumb: if you'd want to point at it to answer "where did this
come from, what is this built on," it belongs in source-context.
